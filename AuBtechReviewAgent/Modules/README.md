# Modules

One folder per kind of review. A module is the recipe for one kind of review: the order of its steps, its own ledger, its pages and its report, built on the shared core and steps in the other folders. Each module implements `IReviewModule` (in `Pipeline/ReviewModule.cs`) and is listed in `ReviewModules.All`. The cards on the start page are declared by the module that runs them, so five cards need only two modules: the rapid and living reviews are variants of the systematic review, and the grey literature review is the multivocal review with only grey sources.

`Systematic/` is the PRISMA 2020 systematic review. Its runs are still done by `PrismaReviewEngine`, and its PRISMA-only files move into this folder step by step. `Multivocal/` is the multivocal literature review (Garousi et al., 2019). It is not built yet, so its cards say "coming soon". Listing it in `ReviewModules:Preview` (read only in Development) opens its planning form at `/mlr` (`MultivocalPlan.cs` holds the answers, `MultivocalProtocol.cs` writes the protocol and `MultivocalPlanner.cs` starts a planned run); in production that page is "not found". The free grey literature searches (Stack Exchange, GitHub, Hacker News, OpenAlex reports and theses, Zenodo) are in `Multivocal/GreySources/`, behind `IGreySource`; `GreySourceCatalog` says which of the plan's searches are built. `MultivocalSearch.cs` runs them for a planned run, with the plan's grey search strings and stopping rule, saves every raw answer with its SHA-256 and writes `multivocal-ledger.json`. `MultivocalPages.cs` keeps the text of a found source's page through `WebPages/PageFetcher.cs`, which obeys robots.txt, paces each site and connects to public addresses only. Pages in a module folder get their usings from `Modules/_Imports.razor`.

A module is done only when it passes the module test kit in `AuBtechReviewAgent.Tests/Modules/`, which runs it end to end on a poisoned fake run and checks the rules of `AGENTS.md`.

The rule for where a file goes: if more than one kind of review uses it, it belongs in a shared folder (`Search/`, `Screening/`, `Verification/` and so on); otherwise it belongs in its module's folder. The design is in [docs/roadmap/review-modules.md](../../docs/roadmap/review-modules.md).
