# Synthesis

Turning the evidence into text. `ReviewEvidence.cs` is the evidence every kind of review writes from, in one shape: the numbered sources with their reference lines, verified findings and text, and the themes with their sources and codes; a module fills it (the systematic review in `Modules/Systematic/SystematicEvidence.cs`) and the writing steps read only it. `ReviewWriter.cs` holds the writing stages every kind of review shares: the grounded outline, one cited subsection per theme with its fill pass, the discussion, the automated peer review with one revision, and the title, abstract, rationale and objectives written last from the checked sections; `WritingProfile` gives the words a review is named by in the prompts (the systematic review's are the defaults, so its prompts stay as they were, which `Golden/systematic-writing-prompts.txt` in the tests checks word for word). The class is split by stage: the outline, theme subsections and discussion are in `ReviewWriter.Themes.cs`, the peer review in `ReviewWriter.PeerReview.cs` (its critique gets the facts about the evidence base, the sources left out of the themes and each theme's sources, and a theme revision may not cite outside its theme), the closing sections and their checks in `ReviewWriter.Closing.cs`, the answers to the research questions, which the discussion call writes first and the closing sections and the front matter then get as checked text, in `ReviewWriter.Answers.cs`, the rule and the code check that keep what the sources found apart from the review's own reading (`EvidenceThenReadingRule` and `UncitedAttribution`: a finding ends with its citation, and an uncited sentence may not report one) in `ReviewWriter.Attribution.cs`, the front matter and practitioner summary in `ReviewWriter.cs`, and the research questions in the prompts (`AimBlock`) and the text about them written in code (the objectives, and the answer to a question no evidence bears on) in `ReviewWriter.Questions.cs`. With research questions the coding sees them and the eligibility criteria, codes what bears on any question and names the questions each code bears on (`ThematicSynthesis.CodingQuestions.cs`), the codebook organises the themes by question and lists the questions no code bears on, and every writing step from there on sees the questions; without them every prompt is as before. `PrismaReviewEngine.Thematic.cs`, `ThematicSynthesis.cs` and `ThematicSynthesis.Codebook.cs` code the verified findings, group them into themes and write one cited subsection per theme, with guards in code so no study and no citation is lost on the way. `GroundingContextBuilder.cs` chooses which excerpts each paper contributes. `ArtifactBuilder.cs` builds the diagram, table or list from the finished text (its shape is in `ReviewArtifact.cs`; the codebook's in `ThematicCodebook.cs`), and `MermaidSanitizer.cs` keeps its diagram code safe. `StylisticRefinerUtility.cs` copy-edits the free prose, and `ProseCleaner.cs` turns any Markdown the model wrote back into plain prose before the citations are checked.
